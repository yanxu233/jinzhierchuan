## 这是什么

**Mochi 字卡传讯**是一个纯前端的情侣模拟聊天 PWA：打开网页，就能和「TA」用字卡聊天、互动、玩小游戏、养花园、写信、看朋友圈、听音乐、记日历……所有内容都是**预先编写的字卡与随机逻辑**，纯属虚构娱乐。

它的定位不是「小手机」，而是一个**字卡传讯工具**：聊天回复、情绪、心意、交流意图、查岗、邀请、互动卡片等大量内容都由字卡驱动，并且几乎每一项都能自己改、自己调概率、自己开关。

- **纯本地**：没有后端、没有账号体系，所有数据只保存在你自己的设备浏览器里，不会上传到任何网络。
- **可安装**：支持 PWA，安卓 Chrome / Edge、iOS Safari 都可以「添加到主屏幕」，像 App 一样打开。
- **可离线**：Service Worker 预缓存页面与脚本，断网也能继续使用已加载的内容。
- **完全免费**：作者个人出资、花时间搭建，不收取任何费用，也没有任何付费功能。

> **项目状态：** 本站已于 2026-09-30 起停止功能更新（永久停更），此后仅可能发布必要的声明修正。停更不等于下线，代码继续公开，可自行二改自用。

## 技术栈

- **原生前端**：HTML + CSS + JavaScript，无框架、无运行时依赖。
- **构建**：`build.mjs`（Node，无第三方依赖）把 `src/css` 按固定顺序合并进 `index.html`，把 `src/js` 按依赖顺序拆成 `js/*.js` 外置脚本（`defer` 加载），同时生成 `sw.js`、`version.json`、`manifest.json`、`notice.json` 与图标。
- **PWA**：Service Worker 预缓存 + 版本戳更新；可添加到主屏幕；离线可用。
- **存储**：`localStorage`（键前缀 `xy-home-v2:`）+ `IndexedDB`；多联系人使用独立命名空间 `xy-home-v2:<cid>:`；启动时从 IndexedDB 回填 localStorage。**无后端、无账号、不上传。**
- **移动端适配**：`visualViewport` + 安全区变量 `env(safe-area-inset-*)` 适配刘海屏与地址栏；安卓输入框使用 `contenteditable` 代理；iOS 使用模拟全屏；支持暗色主题。
- **质量保障**：`build.mjs` 的修复哨兵（`FIX_SENTINELS`）+ `tools/verify-*.mjs` 行为回归 + Playwright 无头 Chrome / WebKit 布局验证 + GitHub Actions。

## 项目结构

```text
.
├─ src/                     # 源码
│  ├─ template.html         # 页面骨架，构建时注入样式与脚本
│  ├─ css/                  # 19 个样式源文件，按顺序合并
│  ├─ js/                   # 90 个脚本源文件，按依赖顺序合并
│  └─ pwa/                  # manifest / sw / notice / 图标源文件
├─ build.mjs                # 唯一构建脚本
├─ tools/                   # 回归验证脚本（Playwright）
│
├─ index.html               # 构建产物：页面（CSS 已内联）
├─ js/                      # 构建产物：外置脚本（defer 加载）
├─ sw.js                    # 构建产物：Service Worker
├─ version.json             # 构建产物：部署时间戳
├─ manifest.json            # 构建产物：PWA 清单
├─ notice.json              # 构建产物：开屏公告
├─ icon-*.png               # 构建产物：应用图标
├─ .nojekyll                # GitHub Pages：跳过 Jekyll
├─ LICENSE                  # 自定义许可协议
└─ README.md
```

> **不要手改构建产物**（`index.html`、`js/`、`sw.js`、`version.json`、`manifest.json`、`notice.json`、`icon-*.png`）。所有修改都在 `src/` 里做，然后执行 `node build.mjs`。

## 本地运行与构建

需要 Node.js 18+。

```bash
# 1. 构建（生成根目录产物）
node build.mjs

# 2. 只检查修复哨兵，不写产物（改完 src 后建议先跑）
node build.mjs --check-sentinels

# 3. 本地预览（必须用 HTTP 服务器，file:// 无法注册 Service Worker）
npx serve .
# 或
python -m http.server 8080
```

然后打开 `http://localhost:8080`。

### 回归验证（可选）

```bash
npm install          # 安装 Playwright
npm run verify       # 无头 Chrome 布局验证（390×844 / 360×640）
npm run verify:webkit # WebKit 引擎验证（iOS 方向）
npm run verify:all   # 全部回归脚本
```

## 部署到 GitHub Pages

本站是纯静态站点，仓库根目录就是发布目录，不需要额外的构建服务。

1. Fork 或克隆本仓库。
2. 修改 `src/` 下的源文件（如需要），执行 `node build.mjs`。
3. 把 `src/` 改动和构建产物（`index.html`、`js/`、`sw.js`、`version.json`、`manifest.json`、`notice.json`、`icon-*.png`）**同一次提交**。
4. 打开仓库 **Settings → Pages**，Source 选择 **Deploy from a branch**，分支选 `main`，目录选 `/ (root)`。
5. 等待 Pages 构建完成，访问 `https://<用户名>.github.io/<仓库名>/`。

补充说明：

- 仓库已包含 `.nojekyll`，不会走 Jekyll 处理。
- 页面内的资源路径都是相对路径（`./`），部署在子路径下也能正常工作。
- 修改后如果浏览器仍显示旧版本，通常是 Service Worker 缓存；刷新页面或重新打开即可，`sw.js` 的缓存名每次构建都会变化。
- 不要提交 `node_modules/`（已在 `.gitignore` 中忽略）。

- 本站不会加云存储，也不会把数据上传到任何服务器。
